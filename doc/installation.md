# installation

## configuration

### UX rev 1 (rev6) — start here

prerequisites and the submodule init are in [building](#building-the-source-code) below. the
board carries a pico w or a pico 2 w; **the image must match the module** — the wrong one leaves
the pico silent (no usb, no serial, no led). these are the configurations ci builds:

```shell
# pico w, bluetooth, ssd1306 display
$ cmake -B build/ -S . -DBOARD_TYPE=BOARD_HIDPICO_REV6 -DPICO_BOARD=pico_w -DENABLE_BLUETOOTH_HID=ON
# pico 2 w
$ cmake -B build/ -S . -DBOARD_TYPE=BOARD_HIDPICO_REV6 -DPICO_BOARD=pico2_w -DENABLE_BLUETOOTH_HID=ON
# plain pico (no bluetooth)
$ cmake -B build/ -S . -DBOARD_TYPE=BOARD_HIDPICO_REV6 -DPICO_BOARD=pico
$ cmake --build build/
```

then flash `build/src/amigahid-pico.uf2` over [bootsel](#usb-bootsel). rev6 has dedicated
real-keyboard input pins, so `PORT2_ROLE=KEYBOARD` does not apply (the build refuses it). see
the [board guide](./ux-rev1.md). everything below is for the earlier boards unless it says otherwise.

### general options

the file [CMakeLists.txt](/CMakeLists.txt) has a small number of configuration options. the critical aspects of the build can be specified on the `cmake` commandline; you should not normally need to edit the [CMakeLists.txt](/CMakeLists.txt) file unless you are doing something outlandish.

### controller port 2 role

controller port 2 can be built in one of two roles via `-DPORT2_ROLE=`:

* `JOYSTICK` (default) - port 2 is reserved for (future) joystick emulation.
* `KEYBOARD` - port 2 is repurposed as an input for a real amiga keyboard, decoded and merged with the usb/bluetooth path. wire port 2 to the keyboard (not the amiga); see the [hardware](./hardware.md) guide for the adapter pinout.

```shell
$ cmake -B build/ -S . -DBOARD_TYPE=BOARD_HIDPICO_REV4 -DPORT2_ROLE=KEYBOARD
```

## building the source code

prior to installation, ensure you have cmake, gnu make and gcc targetted to arm-none-eabi. you should be able to find these in debian. homebrew in macos has a cask for prebuilt gcc 10 binaries from arm. under windows, you're probably best off using wsl.

clone the repository. once cloned, you'll need to initialise the pico sdk and external dependency submodules.

```shell
$ git submodule update --init --recursive
```

tinyusb and the cyw43 driver are pinned separately in `lib/` so they can be updated independently of the pico sdk. to use another checkout, pass the corresponding path to cmake:

| dependency | cmake option |
| --- | --- |
| tinyusb | `-DPICO_TINYUSB_PATH=/path/to/tinyusb` |
| cyw43 driver | `-DPICO_CYW43_DRIVER_PATH=/path/to/cyw43-driver` |

when it's ready, start cmake off; you'll need to specify the board type you're using. if you omit it, you'll get a build for the default target, amigahid-pico standard pcb revision 4. this is akin to running:

```shell
$ cmake -B build/ -S . -DBOARD_TYPE=BOARD_HIDPICO_REV4
```

but you can also run this to get a revision 2 pcb build (the pin assignments are different):

```shell
$ cmake -B build/ -S . -DBOARD_TYPE=BOARD_HIDPICO_REV2
```

targets: `BOARD_HIDPICO_REV2`, `BOARD_HIDPICO_REV4` (also the r5 pcb) and `BOARD_HIDPICO_REV6` (the UX rev 1 board). revision 3 users should not use the pcb as it has a faulty pin assignment which can spontaneously reset the rp2040 controller, so please do not use it.

you can also enable generation of debug symbols so as to use `openocd` and `gdb` to debug a running target over serial-wire debug (swd). to do this, add the parameter `-DCMAKE_BUILD_TYPE=Debug`, e.g.:

```shell
$ cmake -B build/ -S . -DBOARD_TYPE=BOARD_HIDPICO_REV4 -DCMAKE_BUILD_TYPE=Debug
```

a 'Release' build is generated by default.

if you have an oled display fitted, you'll also need to tell the build which controller it uses. the default is the ssd1306.

```shell
$ cmake -B build/ -S . -DDISPLAY_CONTROLLER=DISPLAY_SSD1306
```

The 1.3" panels are usually driven by an sh1106 instead: 

```shell
$ cmake -B build/ -S . -DDISPLAY_CONTROLLER=DISPLAY_SH1106
```

then build:

```shell
$ cmake --build build/
```

see next section for installing on a pico.

## installing on a pi pico (or similar) board

for the simplest option, pick usb. swd is good for remote debugging and reprogramming without detaching devices.

### usb (bootsel)

take a powered down pico (on the ux board: unplug every supply and wait 15 s, or hold bootsel while shorting the RUN castellation to GND — the bulk capacitors keep it alive through a quick unplug), hold the bootsel button and attach a micro usb cable. copy the `amigahid-pico.uf2` file from `build/src/` to the mounted usb storage volume. the pico will spontaneously disconnect, and when it comes back, it will be running the amigahid-pico code. disconnect usb and attach an otg adapter.

### serial wire debug (swd)

swd uses openocd to program the flash memory attached to the rp2040.

to use swd to install the firmware, see chapter 5 of [getting started with raspberry pi pico](https://datasheets.raspberrypi.com/pico/getting-started-with-pico.pdf#%5B%7B%22num%22%3A21%2C%22gen%22%3A0%7D%2C%7B%22name%22%3A%22XYZ%22%7D%2C115%2C841.89%2Cnull%5D).
